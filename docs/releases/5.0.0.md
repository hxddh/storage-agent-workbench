# Storage Agent v5.0.0

**A fully native Agent, rebuilt on one item stream. The estate is the object; Agent Tasks are how work is done; one stream is the truth.**

## Summary

v5 is a clean rewrite of the Sidecar runtime, its persistence and the window. It keeps what the product is for — a read-only, bounded Agent that looks after object storage and remembers the estate — and removes the layers the product had accumulated around it.

- **One item stream.** Every event of a task — the Direction, the Agent's commentary, each tool call, its progress and output, the conclusion, a steer, a compaction, lifecycle notices — is one append-only row with a global sequence number. The page, the report, the audit and the trace are projections of it. Followers resume by sequence; nothing is inferred from prose.
- **Forks.** A task is a tree of turns. Edit any Direction and the Agent answers the new version on its own branch; ‹ 1 of 2 › switches between versions. The model only ever sees the branch being read.
- **The native Agents SDK, used thinly.** One streamed run per turn with typed function tools, input guardrails for scope, per-tool timeouts, the SDK's tool-output trimmer, model retries and tracing processors. Steer is injected into the running loop; Stop cancels it and keeps the partial work.
- **Responses first, Chat Completions everywhere.** On the official OpenAI endpoint the Agent runs on the Responses API: tool groups are deferred behind hosted tool search, long turns compact server-side, nothing is stored provider-side. Every other endpoint — hosted or local — runs on Chat Completions with all tools.
- **A new window.** Result-first task page with live work, forks and a side pane (Evidence · Report · Activity); a home that says what to care about now; a quieter sidebar; a palette; compact Settings with the watch per account.
- **Quick Ask and the tray.** A small always-on-top window (⌘⇧Space) for one question, and a tray item whose tooltip says what needs care.
- **An official MCP server.** The opt-in read-only bridge now runs on the official MCP Python SDK over Streamable HTTP.
- **Upgraded dependencies** throughout (below), and a lean frontend with no UI dependency beyond React.

## Why a major version

Everything below the product changed: the database (a fresh `storage-agent.db`), the HTTP API (`/tasks`, `/providers/*`), the runtime, the frontend architecture. The v4 database is never modified; a one-shot importer brings providers, the estate and past results across.

## What changed

### Runtime (`sidecar/app/agent/`)
- `runtime.py` — one loop thread; a worker per task drains queued turns; submit / steer / stop / withdraw / resume / recover; finalize on budget or recoverable failure; portable compaction before a turn; a title step after the first answer.
- `recorder.py` — the only writer of a turn's items; streamed text sanitized (secret-shaped strings masked before anything is published); throttled progress (≤ 1/s, ≤ 120 per call).
- `session.py` — items → model input for a branch (completed calls replayed with what the model read; a dangling call gets an "interrupted" output; the latest compaction first).
- `tools/` — a declarative registry (`@tool`) replacing hand-written wrappers: scope guardrail, clamped bounds, timeouts, budgets, redaction, the untrusted-data envelope, audit — in one place for every tool.
- `models.py`, `prompt.py`, `errors.py`, `tracing.py`, `safety.py`.

### Persistence (`sidecar/app/core/`, `migrations.py`)
- One migration: settings, providers, tasks, turns, items, artifacts, datasets, the estate, audit, spans.
- `importer.py` — first start reads a sibling v4 `app.db` read-only: model and storage providers (vault references carry over), the estate and Issues with their history, watch schedules, the price table, and each task's Directions, answers and conclusions.

### API (`sidecar/app/api/`)
- `/tasks` (+ turns, steer, stop, withdraw, resume, head, files, artifacts, report, trace), `GET /tasks/{id}/events?after=` and `GET /events` (SSE), `/estate`, `/issues`, `/estate/watch`, `/providers/models`, `/providers/clouds`, `/settings`, `/skills`, `/health`, `/mcp` (opt-in).

### Window (`frontend/src/`)
- `api/` (the only Sidecar client), `store/task.ts` (one reducer over snapshot + SSE), `store/derive.ts` (pure projections), `shell/`, `home/`, `task/`, `composer/`, `inspector/`, `settings/`, `quick/`.
- Navigation uses View Transitions; dialogs are native `<dialog>`; motion is CSS and honours reduced motion.

### Shell (`src-tauri/`)
- Quick Ask window and ⌘⇧Space; tray (Open · Quick Ask · Quit, tooltip = what needs care); `open_task_in_main`, `set_tray_status`; the View menu gains Quick Ask; the custom Find item is gone (the webview's own find applies).

## Unchanged

The safety floor: secrets only in the encrypted vault; storage read-only; scope enforced server-side; the one data-moving tool bounded to 500 files / 256 MiB per call with disk headroom, audited and stoppable; the survey capped at 500 buckets; the watch opt-in, off by default, bounded; raw rows never reach the model; no chain-of-thought persisted.

## Removed

Everything the new model makes redundant: sessions/runs/executions/work-results tables and their routes, the Decision history, remediation plans, baselines and drift, per-task revisits, the investigation memory tables, the provenance projection, the find bar, the shortcuts sheet. Their useful outputs are covered by the item stream, the estate and the report.
