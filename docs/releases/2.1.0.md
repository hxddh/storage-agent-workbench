# Storage Agent v2.1.0

**Native agent: nothing waits for approval, the model keeps no plan, and interrupted work continues on its own. No migration (head stays 031).**

## Summary

v2.0.0 made a Task open on what the Agent concluded. The Agent itself still behaved like a cautious assistant:
- it stopped mid-turn to ask before importing evidence or scanning a large account;
- it painted a checklist it maintained for the user;
- after a Sidecar restart it waited for someone to press Resume.

v2.1.0 makes it act like a native agent. It works inside hard server-side bounds instead of asking, it shows the real work as it happens instead of a plan, and it picks up interrupted work by itself. **Stop** is the user's brake.

The UI was refined to match:
- tool rows say what the Agent did;
- the Result has one quiet meta line and a lead-paragraph answer;
- live work stays visible until the turn settles;
- everything that opens in place eases in.

## Review of v2.0.0 (what this release corrects)

This review covered the rendered window: the real-Sidecar gallery, in both themes and both languages.

- **The Agent stopped to ask.** An evidence import or a survey above 100 buckets parked the Execution on an approval card. The card offered three buttons, a policy lived in a separate Settings pane, and the task sat in *Waiting for approval* until someone answered.
- **A plan the user did not need.** The `update_plan` checklist duplicated what the tool rows already showed, one card per turn.
- **Restarts left work behind.** An interrupted Execution showed a Resume banner and did nothing until pressed.
- **The live view was mostly empty.** While working, the page often showed only *In progress · Working*. Once the model started writing, its tool rows collapsed away.
- **Rows read like code.** `head_bucket bucket-1 … 200` in monospace, with a red name on failure.
- **The Result head read like debug output.** *Result 38w ago* on one line and *Tool calls 1* on another. The conclusion's answer was set as a heavy headline, and the next steps were a grid of pill buttons.
- **Chrome details.**
  - The task state sat alone at the far right of the title bar.
  - Settings → General was a large empty pane.
  - *Needs attention* was red in the title bar but yellow in its banner.
  - Nothing moved when things opened.

## What changed

- **Bounded, not gated.**
  - `import_evidence` runs inside the Execution, from a source the task's account survey discovered.
  - It is clamped to **500 files / 256 MiB** per call, whatever the model asks for.
  - It is refused, with nothing downloaded, when the data directory would keep less than 1 GiB free.
  - Each import is audited as `approved_by=agent`.
  - It checks Stop before downloading, and its result says when coverage is partial.
  - `survey_account` runs up to its 500-bucket hard cap and reports coverage through `truncated`.
  - Security rule 7 now reads "bounded, audited, stoppable" instead of "confirmation".
- **No approval anywhere.** Removed:
  - `runtime.request_approval`;
  - the approval policy and `/settings/approval-policy`;
  - the decision resolve route;
  - `pending_decisions` in task state, `task.status` and the typed context;
  - `requires_decision` on the task list;
  - the `needs_decision` derivation.

  Decision rows stay readable as history, and restart recovery withdraws any left pending.
- **No model plan.** `update_plan`, `plan.updated` and `plan` turn items are removed. Older ones are ignored on read and replay.
- **Work continues itself.**
  - Restart recovery submits one continuation per interrupted Execution: a `kind=resume` Execution carrying the Direction and a `[resume]` note.
  - It never continues a continuation that was itself interrupted, so there is no crash loop.
  - Without a usable model, the task keeps a manual **Resume** whose copy says why.
- **Tool rows read as work.**
  - A localized verb (*Checked bucket*, *检查桶*) comes first.
  - The target is quiet in mono and the result is a muted note.
  - Status lives in the glyph.
  - The raw tool name stays on the row as `data-tool` and tooltip.
- **The Result, refined.**
  - One meta line: *Result · Jan 1 · Evidence 2 · Gaps 1 · Tool calls 5*. Times are relative for a week, then a calendar date.
  - The answer is one lead paragraph, the same size with or without findings.
  - Next steps are a short list of asks (→ text) that fill the Composer.
  - The Report row lost its explanatory subtitle.
- **Live work stays visible.** Every *Worked for …* group stays open until the turn settles, and new commentary and rows ease in.
- **Chrome.**
  - The title and its state are one centred group.
  - Work-log Directions sit one step below the Result's lead.
  - Sidebar rows are lighter and denser.
  - *Needs attention* is one warn dot everywhere.
  - Settings states the safety floor in General. There is no Safety pane.
  - The native menu's ⌘I item is *Show Details*.
- **Motion.** Detail rows, finding details, folded answers, worked rows and new live items share one short reveal (`reveal-in`, `--duration-base`). `prefers-reduced-motion` removes it.
- **Detail rows** are Evidence · Report · Execution. The cost, remediation-plan, baseline and drift engines remain, and the Agent narrates what they return.

## Preserved

- The window: sidebar · title bar · one Task document · one Composer. Result-first page order.
- Read-only storage: no mutating or destructive tool, and provider scope enforced server-side.
- Secrets only in the vault, bounded and sanitized context, and no chain-of-thought.
- One submit path, and durable Executions with reconnect by sequence.

## Contracts

- **Sidecar:** `tests/test_v210_native_agent.py` pins:
  - the bounded import: clamp, disk refusal, Stop, no Decision, `approved_by=agent`;
  - automatic continuation: once, no loop, manual Resume without a model.

  Also rewritten:
  - `test_v111_native_turns.py` and `test_v112_native_protocol.py`: no plan tool, no approval routes, a bounded survey;
  - `test_agent_tasks.py`: legacy Decisions never block a task and are withdrawn on restart.

  `test_v096_decision_supersede.py` is retired.
- **Frontend:**
  - `architecture.test.ts` adds "never pauses the Task for approval and never paints a plan".
  - The turn-model, task-state, live-runner and Execution-detail tests replay pre-2.1 frames and ignore them.
  - Tool-row tests query by the raw name in the title.
- **E2E:**
  - `native-agent.spec.ts` replaces the approval-policy and plan specs: an import call runs in the turn with no card, and Settings has no Safety pane.
  - Row assertions use `data-tool`.
- **Docs:** CLAUDE.md (§1, §4, §5, §6 rule 7, §7, §8, §9) and the canonical docs describe the native agent. The documentation contract moves to v2.1.0.

## Known gaps

- The import bound is fixed at 500 files / 256 MiB per call. It is not a user setting.
- An automatic continuation re-runs the interrupted turn's read-only calls. Their results are not reused.
- Tool labels cover the registered tools. A new tool shows its own name, spaced, until it gets a label.
