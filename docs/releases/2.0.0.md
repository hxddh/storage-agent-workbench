# Storage Agent v2.0.0

**Result-first Task: a Task opens on what the Agent concluded, not on the tail of a transcript. Migration 031.**

## Summary

v1.19.0 made each turn a document section. The page still read in time order, though, so opening a Task landed at the end of a transcript, often halfway down a 24-row table. v2.0.0 changes what the Task page *is*.

A Task now opens at its top, on the latest **Result**. The Result starts with the conclusion the Agent recorded:
- the answer, in one or two sentences;
- the findings that support it, most severe first;
- next steps the user can put into the Composer.

Below the conclusion come the full answer, the figures, and the durable outputs as rows that expand in place. The whole history lives underneath in the **Work log**.

The conclusion is structured data recorded by the runtime. It is never guessed from prose.

## Review of v1.19.0 (what this release corrects)

This review covered the rendered window: all 55 real-Sidecar gallery states, in both themes and both languages.

- **The answer was not first.** Opening a Task scrolled to the end of the document. The reader met the tail of the last answer (often the middle of a table) before any conclusion.
- **Content had no shape.** The Work Result was the model's Markdown in generation order. Nothing said what was concluded, how severe it was, or what to do next.
- **The runtime's structured truth was hidden.** Grounding (evidence used, gaps) and findings existed, but were buried in a side panel or not shown at all.
- **The Artifacts panel was mostly empty.** Four of its five sections were usually placeholder copy ("No remediation plan yet — …"), and Execution detail repeated the whole answer in a narrow column.
- **Raw data dominated the reading column.** A 24-row table rendered whole, in the middle of the page, with no preview, sorting or folding.
- **Scrolling fought the reader.** A convergence loop chased a moving bottom, a pin detector tracked whether the reader was at the end, and *Jump to latest* floated over the content.

## What changed

- **Runtime-recorded conclusion (`record_conclusion`).**
  - A new core tool, budget-exempt: `record_conclusion(answer, findings[{title, severity, detail}], next_steps[])`.
  - Bounds: answer ≤ 400 chars; ≤ 8 findings; severity is `high | medium | low | info`, with aliases mapped; ≤ 4 next steps.
  - Every string is redacted and has hidden reasoning stripped. The last call of a turn wins, and it is never a tool row.
  - The runtime appends `conclusion.recorded` and persists the conclusion on the assistant message (`session_messages.conclusion`) and on the durable Work Result (`work_results.conclusion_json_sanitized`). This is **migration 031**.
  - Evidence and gaps stay derived from the tool trace. A turn without the call has no conclusion.
- **Result-first Task page.** The page now runs, from the top:
  1. banners;
  2. the work in progress: its Direction, live Execution and approval card, plus its conclusion as soon as it is recorded;
  3. the **Result**: kicker and time; conclusion; grounding line (evidence · gaps · tool calls); full answer; figures; detail rows;
  4. the **Work log**.
- **Scrolling.** The page opens at scrollTop 0. A new Direction brings the reader back up to the work in progress. Nothing follows the end. The pin tracking and *Jump to latest* are gone.
- **Findings read by severity.** Each finding has one status dot:
  - high: danger;
  - medium: warn;
  - low: grey;
  - info: hollow.

  A finding with detail expands in place.
- **Next steps are asks, not actions.** A next step fills the Composer. The user still delegates it.
- **Detail rows replace the Artifacts panel.**
  - Evidence, Report and Execution are rows under the Result. Remediation Plans and Baselines & Drift appear only when they exist.
  - Each row expands in place. ⌘I opens the first row that exists. Tool rows, provenance marks and the palette open the matching row.
  - There are no empty placeholders, no side panel, no overlay, and no focus trap.
- **Work log.**
  - Every turn keeps its Direction heading, commentary, *Worked for …* group, plan and approval.
  - Older answers fold to one line: the conclusion's answer, or else the answer's first line.
  - The latest turn points up to the Result instead of repeating it.
  - An open Find shows folded answers in full.
- **Tables that read.**
  - A table longer than 12 rows previews its first 8 and expands in place.
  - Column headers sort; sizes (`328 GiB`), money and percentages sort numerically.
  - Folded rows stay in the DOM, and an open Find reveals them.
  - There is still no inner scroller and no pagination.

## Preserved

- The window: sidebar · title bar · one Task document · one Composer.
- One submit path, Decision-gated data movement, and approval cards inline where the gated tool raised them.
- The v1.18 security floor, and the v1.19 document grammar (a Direction heading, no bubble).

## Known gaps

- A reload that lands exactly while an execution is finishing shows the second turn a moment later rather than at once. Persisting the Direction when the execution starts is a follow-up.
- Figures have no hover layer yet.
- How well the conclusion reads depends on the model calling `record_conclusion`. A model that never calls it gets an honest answer-only Result.
