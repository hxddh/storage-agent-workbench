# Storage Agent v1.03.0

v1.03.0 keeps the v1.02 native Agent window and adds **modern native-agent extensions** — bounded, opt-in, same security floor. No migration (head remains **027**), no new top-level navigation.

## Added

- **Local model providers** — `ollama`, `lmstudio`, `vllm`, `llama.cpp`, `openai-compatible` without a stored key. The client sends `not-needed`, falls back to localhost defaults (`11434/v1`, `1234/v1`, `8000/v1`), and is probed via `GET {base}/models` like cloud models. `model_budget` adds conservative windows for local families. Settings shows *Local model — key not required*.
- **User skills** — `STORAGE_AGENT_DATA_DIR/skills/*/SKILL.md` and `STORAGE_AGENT_SKILLS_DIR` are merged into the catalog next to the 20 bundled StorageOps skills. User skills shadow bundled ones by name. No code is executed; only `SKILL.md` guidance text is returned via `read_skill`, bounded to `MAX_CHARS_PER_SKILL`. `GET /skills` lists the merged catalog.
- **Read-only MCP bridge** — `GET /mcp/status`, `GET /mcp/tools`, `POST /mcp/tools/call` re-export the whitelisted read-only storage tools (list/head/get/presigned/latency/TLS/survey etc.) to a *local* MCP client. Disabled by default; `STORAGE_AGENT_ENABLE_MCP=1` enables it. Same allowlist/scope/redaction/bounds as the agent.
- **Observability export** — `GET /agent-tasks/{id}/export/otel` (bounded `execution_events` + `tool_calls` + `turn_metrics` + `task_artifacts`, `events_truncated` flag) and `GET /observability/export` (global task/execution counts + sanitized provider presence). OTel-inspired JSON, auth-gated, no new tables. Settings surfaces it under *Observability*.
- **OS-native shell** — Tauri `dialog`, `notification`, `opener`, `deep-link`, `global-shortcut`, `updater` plugins (gated, inert until signing pubkey/endpoints are configured). `singleInstance` remains first. Frontend `useDeepLink` handles `storage-agent://task/<id>`. Deep links and global hotkey are best-effort in browser.
- **Example user skill** — `examples/skills/my-local-runbook/SKILL.md` as a starting point for teams.

## Changed

- `ProvidersView` now understands local types (`ollama` etc.): contextual placeholder, local hint, key-optional copy, and `isLocalProvider` detection.
- `SettingsDrawer` now includes `NativeAgentPanel` (skills + observability + MCP) below providers.
- `CLAUDE.md` §10 and `docs/product.md`/`architecture.md`/`roadmap.md` document the gated extensions as additive, not as non-goals.
- Tauri capabilities and `tauri.conf.json` plugins block updated for the OS shell.

## Preserved

- The Agent Task is the application. One Composer (Delegate / Steer+Stop), overlay Review, typed Storage Task Context, durable `task_executions` + `execution_events` (`after=<last seq>`), `task_decisions`, `work_results`, `task_artifacts`.
- Read-only storage tools, no shell/subprocess/raw boto3, secrets only in the encrypted vault, server-side provider scope, explicit Decisions, bounded/sanitized context, no chain-of-thought persistence.
- Migration head **027**.

## Security

Same floor. Local models reuse `keyring_store` and never enter model context. MCP is allowlist-only and reuses `tool_runner` bounds. Skill bodies are guidance text, never executed. Observability exports only already-sanitized rows. Tauri plugins are local-only and add no network surface.

## Known limitations (unchanged)

- Apple notarization / Windows Authenticode / trusted auto-update chain not yet configured (updater is gated and inert).
- macOS x64/universal not produced; Linux x64 and Windows x64 are unsigned/experimental where noted in CI.
