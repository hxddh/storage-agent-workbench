# Storage Agent v1.18.0

**Native core — one Task boundary, one submit path, every data movement behind a Decision. No migration (head stays 030).**

## Summary

v1.17.0 made the window match Codex's quiet Agent surface. v1.18.0 reviews the runtime and code underneath that window against the product invariant, **the Agent Task is the application**, and removes what was not native. The window itself is unchanged apart from one line: a Steer now reads as the user's own *Steered* line where the model loop took it.

## Review of v1.17.0 (what this release corrects)

- **A second submit path.** `POST /runs`, `POST /runs/{id}/message`, `GET /runs/{id}/events` and `POST /runs/{id}/datasets/upload` could start engine work outside any Agent Execution. An in-memory event bus polled every 0.1 s and buffered events nobody subscribed to.
- **Data movement without a Decision.** `POST /evidence-imports/plan`, `/{id}/confirm` and `/{id}/run` downloaded data with no `task_decisions` row, no `approval.opened` event and no approval-policy check.
- **A read that started work.** `GET /agent-tasks` submitted due revisits.
- **A write lock across the network.** `_finish` held the SQLite write transaction open across the title step's model call.
- **A Steer shown as a tool call.** It appeared as a fake `user_steer` tool row live and was dropped from the saved transcript.
- **Python 3.10/3.11 did not run.** `typing.TypedDict` in a pydantic schema fails below 3.12, although the declared floor is 3.10.
- **Session/run vocabulary in product code.** The frontend was written in these terms behind four `*Implementation` wrappers. It also carried 17 unused API clients and 115 dead i18n keys.

## What changed

- **Sidecar.**
  - The routes above and `app/events.py` are removed. Engines run only inside an Agent Execution through `run_service.run_sync`. `/runs` and `/evidence-imports` are read-only.
  - A revisit scheduler (`STORAGE_AGENT_REVISIT_TICK_SECONDS`, default 60 s, floor 5 s) replaces the tick inside the task-list GET.
  - `_finish` commits the Work Result before the title step.
  - The stream segmenter records a `steer` turn item.
  - `plan_tools` uses `typing_extensions.TypedDict`.
- **Frontend.**
  - `AgentTask` is the one composition root. j/k Direction stepping lives in `hooks/useDirectionStepping`.
  - `ExecutionDetail` and `Markdown` are single modules. `LiveTrace` is gone.
  - `useTurnRunner` is the runner itself.
  - The live store is `liveTasks.ts` (`LiveTask`, `useLiveTask`), with `useTaskDocument`, `lib/taskTitle` and `taskId` props.
  - The `api/` adapters export `createTask`, `getTaskRecord`, `updateTask`, `deleteTask`, `getTaskMessages`, `getTaskCall`, `uploadTaskDataset`, `TaskRecord`, `TaskMessage` … over unchanged URLs.
  - `steer.applied` renders as a *Steered* line.
  - Task-state discovery backs off on Sidecar errors (1.5 s → 30 s).
- **Docs.** `CLAUDE.md`, `api.md`, `architecture.md`, `security.md`, `data-model.md`, `product.md`, `roadmap.md` and the banners describe the native core.

## Preserved

- One durable Agent Task runtime.
- Sequence-only stream recovery.
- Steer/stop/resume/verify/revisit semantics.
- Read-only allowlist, vault, redaction, server-side scope, bounded/sanitized context, explicit Decisions, no chain-of-thought persistence.
- Wire URLs and fields are unchanged apart from the removed routes.
- No migration.

## Known gaps

- A crash during the title step leaves an `interrupted` Execution that already has its Work Result.
- A revisit that becomes due while the app is running waits up to one scheduler tick.
- Most runtime tests still use the blocking `SESSION_LOOP` seam rather than the streamed path.
