# Storage Agent v0.94.0

v0.94.0 is the durable Agent Task runtime rebuild. The product model shipped in
v0.93 — Direction → Execution → Decision (when required) → Work Result →
Artifact — stops being a projection over a per-request conversational turn
runner and becomes the runtime's own durable shape. Take the UI away and the
runtime + persistence alone are a task runtime that can keep executing, be
steered mid-flight, wait on a Decision, recover after a restart, and produce
durable Work Results and Artifacts.

## Durable task runtime

- **Agent Task as a durable domain object.** `agent_tasks` rows (1:1 with the
  compatibility session id) carry the task lifecycle — `ready` / `working` /
  `needs_decision` / `needs_attention` / `archived` — derived from durable
  runtime state.
- **Execution as a first-class object.** Each Direction is a `task_executions`
  row with lifecycle `queued` → `running` → `completed` | `waiting` | `failed`
  | `cancelled` | `interrupted`, run by a background execution supervisor
  keyed by durable task identity. Duplicate submits attach through a durable
  `(task, turn_id)` unique index; a new Direction while working queues durably.
- **Structured durable progress.** The append-only `execution_events` log
  (status transitions, tool activity, steer delivery, decision lifecycle,
  work result recording, context versioning) is the only source of execution
  progress, replayable over SSE from any sequence number. Answer deltas remain
  a transient live stream and are never persisted as events.
- **Steer acts on the current execution.** The steer text is injected into the
  running model loop at its next tool boundary; nothing is cancelled or
  re-run. A steer arriving after the loop stopped calling tools becomes an
  automatic follow-up execution.
- **Disconnect-proof and restart-honest.** UI disconnects, task switches, and
  reloads never interrupt executions; reattaching replays the durable event
  log. A Sidecar restart stamps in-flight executions `interrupted` — an
  explicit durable state with a resume affordance — while executions waiting
  on a user Decision are untouched.
- **First-class Decision / Work Result / Artifact.** Confirmation-gated
  proposals open durable `task_decisions` (superseded by newer Work Results,
  resolved with an audit trail; the raising execution stays `waiting` until
  the boundary is crossed). Every finished execution records a `work_results`
  row; reports, executed evidence imports, and analyses index into one
  `task_artifacts` model surfaced in Review.
- **Typed, versioned Storage Task Context.** `task_context_versions` snapshots
  machine state under an explicit schema version; recovery never replays
  messages to rebuild machine state.

## API and compatibility

- New `/agent-tasks/{id}` runtime surface: state, executions (submit / stop /
  resume / SSE event stream with `id: <seq>` resumption), steer, decisions,
  work-results, artifacts, typed context, task-scoped event pages.
- The `/sessions` message endpoints remain wire-compatible as shims over the
  one durable submission lifecycle; `GET /sessions/{id}/turn` now reads
  durable execution rows and stays truthful across restarts.
- Migration 026 (`durable_task_runtime`) backfills every session into a
  durable task, historical assistant messages into Work Results, and current
  confirmation-gated proposals into pending Decisions.

## Security

Boundaries are unchanged and now durable: read-only autonomy, explicit
confirmation for data-moving work recorded as first-class Decisions, bounded
sanitized event payloads, no secrets and no chain-of-thought in the event log,
single Agent, no new tool surface.
