# Storage Agent v0.93.1

v0.93.1 is a documentation and architecture-contract patch for the v0.93 Agent Task product model. It does not introduce a new runtime capability; it makes the shipped v0.93.0 architecture authoritative across contributor, product, API, security, release, and operational documentation so future development cannot drift back toward the retired v0.92 shell.

## Canonical v0.93 documentation

- Rebuilds `CLAUDE.md`, the root README, Product, Architecture, Roadmap, API, Data Model, Tools, Security, Install, Packaging, Release, Signing, and release-smoke documentation around the shipped Agent Task model.
- Establishes the product flow **Direction → Execution → Decision → Work Result → Artifact** and the invariant **Agent Task is the application**.
- Makes `/agent-tasks` the explicit product projection while keeping historical `sessions` / `runs` names documented only as persistence/API compatibility vocabulary.
- Updates the data-model reference through the actual migration head, migration 025.

## Regression prevention

- Adds a documentation contract test to the normal frontend Vitest suite.
- Rejects retired product contracts such as the thread-first shell, SessionRail, Workbench/Surface navigation, and old steering boundaries from current product documentation.
- Guards current runtime facts including `/agent-tasks`, migration 025, explicit Decision boundaries, and the v0.93 release-smoke model.
- Marks v0.92 architecture and release records as historical/superseded rather than allowing them to act as current implementation guidance.

## Release and safety documentation

- Replaces the obsolete thread/session-rail release smoke checklist with Agent Task, Delegate/Steer/Stop, Decision, Work Result, and contextual Review acceptance checks.
- Consolidates the current local encrypted-vault, Sidecar authentication, read-only Tool, provider-scope, data-movement confirmation, redaction, Evidence Import, and deterministic-analysis boundaries.
- Keeps current distribution status explicit: macOS builds are ad-hoc signed and not notarized; Windows builds are not Authenticode-signed.

## Validation

The change is gated by the normal repository matrix: frontend typecheck/lint/unit/build, Sidecar tests, packaged Sidecar smoke, real-Sidecar Playwright E2E and visual review, plus macOS Apple Silicon, Linux x64, and Windows x64 desktop build/runtime verification.
