# Storage Agent v6.0.0

**The estate becomes the place you work from, and fixes close the loop.** v6 keeps the v5 core — one native Agent, one item stream, one submit path, read-only storage — and builds on the existing concepts (Task, item stream, estate) rather than adding modes. There is no plan mode, todo list, approval step, mode switch, sub-agent or workflow builder.

## Summary

- **The estate view.** A new **Estate** entry in the sidebar opens every storage account, an account's buckets (most in need of care first) and a **bucket page**: what needs care, what is known (the posture as last checked), the notes kept about it, and **how it changed** — posture changes and Issue events on one timeline, newest first, each naming its source and the task behind it. *Ask about this bucket* fills the Composer; it never submits.
- **Fix packs.** Every generated fix now comes as an **AWS CLI** command, a **Terraform** resource or the **API document**, copyable, with its notes. The bucket name, endpoint and region are shell-quoted and HCL-escaped, so a hostile endpoint cannot turn a bucket name into a second command in text you paste into a terminal; a name no quoting protects in every shell gets no generated command, and fixes stored by earlier versions are regenerated instead of served as stored.
- **Impact preview.** Before you apply a fix, the Issue says what it would change, from evidence the estate holds: for a public access block, how many requests in the bucket's attached S3 server access logs were anonymous (counts, a time range, a few prefixes — never a requester, an IP or a raw line); for lifecycle rules, whether the bucket's existing rules would be replaced; for encryption, that only new objects change. When the evidence cannot answer, it says **cannot tell** and what would answer it.
- **The verify loop.** Verify re-checks an Issue read-only and resolves it; the next survey, review, verify or watch that sees the problem again marks it *came back* — the loop the fix pack starts.
- **Notes.** You and the Agent keep notes on the estate, an account or a bucket — an owner, an intent, why a setting is deliberate. The Agent writes them with its new `note` tool; accepting a risk with a reason keeps the reason. Every note is visible, editable and deletable, redacted and bounded, and the most recent reach every task as remembered context, inside the untrusted-data envelope (never as instructions).
- **`fix_preview`.** The Agent can present the same fix pack and impact preview inside a task ("Show me the fix for acme-www") without changing the Issue.

## Kernel

- **SDK-native error handling.** A step-budget overrun is finalized through the Agents SDK's `max_turns` error handler, and a model refusal through `model_refusal`; the run reads its branch through an SDK `Session` (`ItemsSession`).
- **Responses websocket.** On the official OpenAI endpoint the main loop uses the Responses websocket transport; an endpoint that refuses it is remembered, and a Turn refused before anything streamed runs again over HTTP. Side steps (title, compaction, finalize) stay on HTTP.
- **Interruptible tools.** Every tool call carries a stop signal set by Stop **or** by the call's own timeout, so a timed-out survey, import or review ends at its next check instead of reading on in the background.
- **Task state follows the branch you read.** A failure on a version you have moved away from no longer marks the task *needs attention*.
- **A real-model eval, opt-in.** `sidecar/tests/live_eval/` drives real Agent turns against a real model (and a local moto S3 — never real cloud): survey + review leave a grounded estate with a conclusion and no secret echoed; a scope refusal is honoured. It runs only with `STORAGE_AGENT_LIVE_EVAL=1` and a key, locally or through the manual *Live model eval* workflow (repository secret `STORAGE_AGENT_EVAL_API_KEY`).
- **Narrow windows.** Below 720 px the sidebar overlays the document instead of squeezing it.

## Data

Migration **2** (`v6_notes_posture_history`) adds `notes` and a bounded `posture_history` (appended only when a bucket's posture changed; the last 50 per bucket). Nothing existing is rewritten.

## API

`GET /estate/providers/{id}/buckets`, `GET /estate/providers/{id}/buckets/{bucket}`, `GET /issues/{id}/impact`, `/notes` (list · create · edit · delete); `POST /issues/{id}/accept` takes an optional `reason`; an issue's `fix` carries `formats`. See `docs/api.md`.

## Unchanged

The safety floor: secrets only in the encrypted vault; storage read-only (a fix is text you apply); scope enforced server-side; the one data-moving tool bounded to 500 files / 256 MiB per call with disk headroom, audited and stoppable; the survey capped at 500 buckets; the watch opt-in, off by default, bounded; raw rows never reach the model; tool output reaches the model inside the untrusted-data envelope; no chain-of-thought persisted.

## Not in this release

- **Auto-update** stays inert: it needs the `TAURI_UPDATER_PUBKEY` / `TAURI_UPDATER_ENDPOINTS` repository secrets.
- Builds remain **unsigned** (no Apple notarization or Authenticode certificate), so the OS may warn on first launch.
- No recurring or scheduled tasks beyond the existing opt-in watch.
