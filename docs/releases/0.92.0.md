Storage Agent Workbench v0.92.0 is a product-level rebuild of the desktop Agent experience rather than an incremental UI polish pass.

### Agent OS workbench

- Replaced the old session-rail + chat-thread + modal-detail composition with a command-center shell built around Investigation Navigation, a compact Command Bar, and replaceable Work Surfaces.
- Added first-class `Timeline`, `Evidence`, `Runs`, and `Report` surfaces with semantic tab navigation and a true Focus mode instead of stacking deep-work overlays on top of chat.
- Kept the Timeline mounted for transport continuity while moving investigation state and deep-work ownership into the workbench layer.

### Evidence and auditability

- Rebuilt Evidence as a document workspace for durable findings, Agent memory, referenced files, activity, audit events, tool-call metrics, errors, and sanitized payload inspection.
- Preserved evidence truth and credential-safety boundaries while making progressive disclosure the default: compact activity rows first, bounded details on demand.
- Moved Runs into the same work area so execution review is an inspectable workflow rather than a transient chat card.

### Durable output and technical rendering

- Promoted Report to a native durable-output surface with copy/save/export actions rather than a centered modal path.
- Reworked answer presentation toward technical-document hierarchy and evidence-linked reading, with less card chrome and a clearer distinction between prose, data, activity, and durable artifacts.

### Steering and interaction model

- Added a shared steering controller for Evidence, Runs, and Report so an investigation can be redirected or continued without returning to Timeline.
- Enforced one mounted Agent input at a time: Timeline owns its primary Composer; deep-work surfaces mount the Workbench steering dock. This removes duplicate input semantics while preserving continuous Agent control.
- Added work-surface keyboard navigation and consolidated application-level surface state instead of duplicating navigation ownership inside the historical Thread implementation.

### Architecture and quality gates

- Decomposed the historical Thread implementation behind explicit workbench/session boundaries and removed legacy Inspector/Report overlay ownership from the main product model.
- Replaced obsolete modal/header E2E assumptions with product-level Agent OS contracts while retaining real-sidecar, accessibility, contrast, credential-safety, persistence, and platform-build coverage.
- Fixed a post-rebuild regression where the hidden steering textarea remained mounted on Timeline, which made the application expose two `Ask Storage Agent…` inputs and broke strict accessibility/E2E selectors.

### Release validation

The release candidate is required to pass the complete CI matrix before merge and again on `main`: Frontend typecheck/lint/unit/build, Sidecar import/tests, packaged-sidecar smoke, real-sidecar Playwright E2E, and macOS/Linux/Windows desktop builds. Release publishing remains all-or-nothing: the GitHub Release stays draft until every platform artifact and checksum has uploaded successfully.
