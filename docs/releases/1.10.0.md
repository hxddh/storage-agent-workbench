# Storage Agent v1.10.0

**Native Agent, Codex parity — a real OS shell, runtime task titles, reasoning effort, native Execution detail and provider panes. Migration 028.**

## Summary

v1.09.0 rebuilt the window. v1.10.0 makes what is underneath it native. The Tauri shell now does what its plugins only promised: a native menu bar, working `storage-agent://task/<id>` deep links, OS notifications when a background Execution settles, a global summon shortcut, and the OS window title — all reaching the window through one bridge and the same command handler the keyboard and the palette use. The runtime names a task after its first Work Result and takes a reasoning effort for models that accept one. Execution detail and the provider panes are native documents. The pre-v0.94 message client is gone.

## Review of v1.09.0 (what this release corrects)

- **A shell that emitted nothing.** Six Tauri plugins were registered; `lib.rs` sent no event. `useDeepLink` listened for `deep-link-request`, which nothing emitted; `useTaskNotifications` and `useGlobalShortcut` were stubs no component mounted.
- **No menu bar.** A desktop agent without App / Task / View / Help and a native Settings item.
- **Titles were the truncated first Direction**, forever.
- **The model chip had no reasoning effort** although the runtime already accounted reasoning tokens.
- **Execution detail** was the v0.5x run page (metrics cards, account profile panel, execution steps) forced into the sheet with `!important` overrides.
- **Provider settings** were the original 680-line form; **Skills & bridges** printed raw endpoint paths.
- `api.ts` still carried `postSessionMessage` / `streamSessionMessage`.

## What changed

- **Shell** (`src-tauri/src/lib.rs`): `build_menu` (App · Edit · Task · View · Window · Help, every custom item one of `MENU_COMMANDS`, emitted as `menu-command`), deep links via `on_open_url` + single-instance argv + cold start (`deep-link-request`, validated ids only), global shortcut (`shortcut-event`), commands `notify`, `set_window_title`, `open_app_folder` (named app-data subfolders only). `tauri.conf.json` registers the scheme. Rust unit tests for link parsing and menu ids.
- **Bridge** (`frontend/src/hooks/useNativeAgent.ts`): `useNativeShell`, `notifyNative`, `setNativeWindowTitle`, `openNativeFolder`, `taskIdFromDeepLink`; browser no-op. `App.runCommand` is the one dispatcher; `useSettleNotifications` posts one notification per background settle.
- **Runtime** (`sidecar/app/task_runtime/titling.py`, migration 028): title step after the first Work Result (bounded, redacted, sanitized, `task.titled`, user rename wins); `reasoning_effort` on the provider API, forwarded only for known-reasoning models (`model_budget.is_reasoning_model`).
- **Composer**: `model · effort` chip with Default / Low / Medium / High for reasoning models; drag-and-drop attach.
- **Sidebar**: ↑/↓ navigation; Rename / Delete from the native Task menu; runtime titles.
- **Execution detail**: a document in the sheet built on `LiveTrace`.
- **Settings**: `settings/ModelProvidersPane.tsx`, `settings/CloudProvidersPane.tsx`, `settings/presets.ts`; `NativeAgentPanel` actions (open skills folder, export trace, copy MCP env var).
- **Cleanup**: dead message client removed; `ExecutionSteps`, `AccountProfilePanel`, `views/ProvidersView` deleted; review notes moved to `docs/history/`; `Cargo.lock` brought in step with `Cargo.toml`.

## Preserved

- `Agent Task is the application` — Direction → Execution → Decision → Work Result → Artifact; one Composer; one submit path (the execution runner); Review as a sheet.
- Read-only allowlist, vault, redaction, server-side scope, confirmation gates. No new tools, no destructive S3, no generic shell. The title step sees only redacted Direction + Work Result text.
