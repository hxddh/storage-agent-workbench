# Storage Agent v0.95.0

v0.95.0 makes the durable Agent Task runtime **user-visible and operable**.
v0.94.0 shipped the durable objects; this release closes the gap between those
objects and the Task the user can actually act on.

The product invariant is unchanged:

> **The Agent Task is the application.**

Canonical work model:

> **Direction → Execution → Decision (when required) → Work Result → Artifact**

## What this release completes

- **Interrupted → Resume** is a task-area action. A `needs_attention` Task whose
  last Execution is `interrupted` or `failed` shows a Resume card that calls
  `POST /agent-tasks/{id}/executions/{eid}/resume` and follows the **new**
  execution's event stream.
- **Queued Directions are visible and cancellable** while another Execution
  runs. Command-center state stays truthful (`working`).
- **Stream recovery is sequence-only.** A dropped SSE reconnects with
  `after=<last seq>` on the durable event log. The blocking `/sessions` POST and
  assistant-id poll are gone from the frontend; those endpoints remain
  compatibility shims.
- **execution_events retention** is bounded at Sidecar startup: only terminal
  Executions are pruned, dual-capped by age and per-execution count, and every
  truncation leaves an explicit `execution.events_truncated` marker. Active and
  waiting logs are never cleaned.
- **Decision cards show bounds and impact** (why confirm, scope, planned
  movement) and expose **Decline**. Review Overview projects durable Decision
  **history** (`pending` / `approved` / `declined` / `superseded`) without a
  new table.
- **Typed Storage Task Context** is injected into the Agent prompt's stable
  half. Restart/resume grounding matches the pre-restart snapshot instead of
  re-deriving buckets, datasets, and open Decisions from thread replay.
- **Cross-evidence correlation** is a deterministic analysis engine (errors ×
  config × addressing; lifecycle × inventory; multipart/versions × cost;
  access-log mix × latency/errors). Findings flow through existing
  summary/findings/memory channels. No second Agent, no new navigation.

## What this release does not change

- Single Agent, read-only autonomy, explicit Decision boundaries.
- No shell/terminal/browser/mutation tools, no CoT in the event log, no secrets
  in prompts.
- Migration head remains **026**. `/sessions` compatibility shims and
  `(task, turn_id)` idempotency stay.
- Execution ownership remains in the Sidecar task runtime.
