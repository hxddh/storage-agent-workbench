# Storage Agent v2.2.0

**Native agent depth: every tool from the first step, Directions that are durable from the start, continuations that pick up where they stopped, and real progress on long work. No migration (head stays 031).**

## Summary

v2.1.0 took the approvals and the plan out of the Agent. v2.2.0 removes the friction that was left in how it works:

- The model no longer has to unlock tool groups before it can use them.
- A continuation after a restart reads what already completed instead of starting over.
- A 500-bucket survey or a 500-file import shows how far it has got.

The window also got the fixes from a review of v2.1.0's rendered gallery.

## Review of v2.1.0 (what this release corrects)

- **An unlock step before the work.**
  - Specialist tools (object forensics, bucket configuration, the survey, the import) sat behind `load_tools(group)`.
  - Every investigation that needed one spent a model round-trip, and a tool row, to open it.
- **Continuations started over.**
  - An automatic continuation carried the Direction and a `[resume]` note, but nothing about what had already run, so it re-ran the read-only calls.
  - The note was stored as the user's Direction, so the Task showed it as the user's words.
- **Long work showed a spinner.** A survey or an import ran for minutes inside one tool row with no sign of progress.
- **The Direction arrived at the end.** Its row was written only when the turn finished. A reload mid-run (or mid-finish) depended on the live stream to show it.
- **Window details.**
  - Revealing a row near the end of a Task scrolled the hidden-overflow window column: `scrollIntoView`, and the browser's own focus/reveal, can scroll an `overflow: hidden` element. The Composer was left floating mid-window over the document.
  - Execution detail painted an empty *No findings* section and the default kind *Direction*.
  - The Resume banner was a filled card with a black button.
  - The Task report still read *Session Report*, *Session goal* and *Timeline of runs*.
  - A one-Direction Task repeated its only turn in a Work log under *Result shown above*.
  - Two gallery states had been captured before v2.1's final CSS: the attention dot and the Resume copy. They are recaptured here.

## What changed

- **Every tool from the first step.**
  - All tools are registered. The instructions say every tool is callable from the first step. `load_tools` is not offered.
  - A model whose resolved context window is **≤ 16k tokens** keeps the grouped disclosure (`load_tools`, the group catalog): carrying every schema would crowd out the investigation. The runtime decides from the window (`limits.tools_gated`); the model never has to.
- **The Direction is durable from the start.**
  - The user's row is written when the execution starts and logged as `direction.recorded`.
  - A failed execution takes back the unanswered row it wrote (`direction.withdrawn`), so a retry never shows the same heading twice. Stop and interruption keep it.
  - A reload mid-run reads it from the document.
  - The latest Result stays in place while a newer Direction is at work. The running Direction heads the work in progress and joins the Work log when its answer lands.
- **Continuations pick up where they stopped.**
  - `kind=resume` and `kind=retry` store the Direction as the user wrote it.
  - Only the model's copy carries the continuation note and a digest of the calls that already completed. The digest is built from the stopped execution's durable `tool.completed` events:
    - it follows up to 3 links of the chain;
    - it holds at most 24 lines and 2,400 characters, dropping the oldest first and saying how many were dropped;
    - it is redacted.
  - A continuation answers under the original Direction row when that row is still the Task's latest message.
- **Real progress on long work.**
  - The survey reports each bucket it finishes and the evidence import each file it downloads, as a durable `tool.progress` event: `{id, tool, done, total, unit}`.
  - Events are throttled to one per call per second, plus the final one, and capped at 120 per call.
  - They carry counts only, never a percentage guessed from time and never row data.
  - A running row reads *120 of 500 buckets* (*120 / 500 个桶*) with a hairline meter under it.
- **Stop ends an import between files.** The download checks Stop before each file and keeps nothing.
- **The window.**
  - Detail rows, the Result pointer, outline links and finding links reveal through `revealInScroller`: only the Task scroller moves. The window columns now use `overflow: clip` (with `hidden` as the fallback), so nothing (not script, focus or the browser) can scroll them, and the Composer stays docked.
  - A one-Direction Task has no Work log. Its Direction, commentary and collapsed *Worked for …* line sit under the Result, just above the detail rows. ⌘F still renders the ordinary log.
  - Execution detail has no empty sections. Only Verify, revisit, resume and retry name their kind.
  - The Resume banner is a quiet note with *Resume* beside *Open Settings*. Its copy says completed calls are not started over.
- **The Task report reads as a Task:** *Task report*, *Goal*, *Analyses*, *Direction n*. The duplicate linked-runs appendix is gone.

## Preserved

- The window: sidebar · title bar · one Task document · one Composer, result-first.
- Read-only storage tools, server-side provider scope, and the import bounds (500 files / 256 MiB per call, 1 GiB disk headroom, audited `approved_by=agent`).
- Secrets only in the vault. Sanitized, bounded context. No chain-of-thought.
- One submit path. Durable Executions reconnect by sequence.

## Known gaps

- The ≤ 16k threshold is fixed. A model whose endpoint under-reports its window keeps the grouped disclosure until its window is configured on the provider.
- The digest carries each call's one-line result, not its full output. A continuation that needs detail repeats that call.
- Progress covers the survey and the evidence import, the two long bounded operations. Other tools finish in seconds and show the running note.
