# Storage Agent v3.0.0

**Design system v3 / Refined native: a full UI redesign on an unchanged runtime. One type scale, one calibrated neutral ladder, one restrained accent, one component library, and a side pane for the Task's durable outputs. Frontend only; no migration (head stays 031).**

## Summary

v2.x made the Agent Task truthful: result-first, no approval, no plan, real progress. v3.0.0 makes the window read like the native tool it is:

- A design system with rules instead of per-surface styling: five type sizes, a neutral ladder that clears AA on every surface, and one indigo accent for what you can act on.
- One component library that every surface composes.
- The Task's outputs (Evidence, Report, Execution) open in a resizable, closable side pane beside the document instead of expanding inside it.
- An empty start, a Result, figures, a palette and Settings redesigned on that system.

The Sidecar runtime, the API, the security floor and the migrations are unchanged.

## Review of v2.2.0 (what this release corrects)

- **No hierarchy of action.** The ink primary made the send control, selected rows, focus rings and links the same near-white or near-black as body text; nothing told the eye what was actionable or selected.
- **Too many type sizes.** Eight sizes (11 to 24px), several one pixel apart, with no single job each.
- **Surfaces restyled controls.** Buttons, badges and inputs were styled per surface, so the same control looked different in the sidebar, the Composer and Settings.
- **Details pushed the document around.** A detail row expanded inside the reading column: long Evidence or a whole Execution detail displaced the Result it belonged to.
- **A bare empty start.** One greeting line and the Composer gave a first-time user no idea what to ask.
- **Figures were hard to read.** No axis ticks, no tooltip, no table fallback, and a series palette that had not been checked for colour-vision deficiency.
- **The palette advertised engines.** The v1.16 *Ask the Agent to…* catalog painted engine names as a menu; the Composer is where work is worded.

## What changed

- **Design system v3** (`frontend/src/index.css`, `docs/design-tokens.md`).
  - Type: five sizes, each with one job — 11 label · 13 UI · 15 reading · 20 conclusion · 28 page title (`--text-2xs … --text-2xl`; older names are aliases).
  - Colour: a calibrated cool-neutral ladder where every text step clears AA on the worst surface (`--hover`). **One restrained indigo accent** — `--accent` fill, `--accent-text` ink, `--accent-dim` selection tint, `--accent-fg` label on fill — used only for the primary action, selection, focus, links and live progress. This replaces the v1.09–v2.2 rule "an ink primary; status is the only colour". Status (danger / warn / success) stays a separate palette.
  - Space and shape: a 4px grid (`--space-1 … --space-12`), three radii (6 / 10 / 14), two shadows (`--shadow-elev`, `--shadow-pop`), 16px icons at a 1.5 stroke.
  - Motion: 120 / 200 / 280ms, all honouring `prefers-reduced-motion`. Sheets rise without fading: an opaque surface never shows what is behind it.
- **Component library v3** (`components/ui.tsx`, styled only in `agent/native-components.css` as `ui-*`): Button (primary / secondary / ghost / selected / danger), IconButton, Kbd, Badge, StatusDot, SectionLabel, Segmented, Field / TextInput / Select. Surfaces compose them instead of restyling.
- **The window.** Still sidebar · title bar · one Task document · one Composer, plus one side pane for durable outputs.
  - Sidebar: a raised *New task* button with its key caps, an in-place title search (Esc clears), the selected row in the accent tint.
  - Title bar: a three-column grid — sidebar toggle · centred name + state pill · side-pane toggle (`titlebar-sidepane`) — with a thin indeterminate progress hairline while work is live.
- **Side pane** (replaces v2.0's detail rows that expanded in place). Under the Result an outputs bar (Evidence · Report · Execution, each with its count, each only when something is behind it) opens one side pane with a tab per output (`TaskDetails` / `TaskInspector` in `components/TaskDetails.tsx`; state in `agent/model.ts` + `AgentShell`'s `TaskDetailsContext`).
  - Resizable: drag the left edge between 352 and 880px; double-click resets; the width is remembered per device.
  - Closable: the close button, Esc, ⌘I.
  - Execution detail opens inside it with one Back.
  - Below ~1100px it overlays the document.
  - There is still no overlay dialog or tabbed destination for artifacts, and no Plans / Baselines entry.
- **Empty start** (`components/TaskStart.tsx`): the greeting as the page's one `<h1>` (28px), one sub line, the Composer, and three real starters — diagnose access · survey the account · analyze an access log — that only fill the Composer and never submit.
- **Result.** An accent *Result* badge with the meta line; the answer at 20px as the focal point; findings as a bordered list with severity badges (High / Medium / Low / Info); next steps as suggestion cards that fill the Composer; the full answer under a section label. Live work shows a pulsing status dot and a live elapsed timer.
- **Composer.** A docked, bordered card with an accent focus ring; a paperclip attach; the model chip reads *Set up a model…* when none is configured.
- **Figures** (`viz/marks.tsx`). Full-width cards with a title and a Chart/Table toggle (every figure has a table view); responsive SVG with y-axis ticks, recessive dashed gridlines and a baseline; 4px rounded data-ends; 2px surface gaps between stacked segments; a hover tooltip per column; legends for two or more series; text in ink tokens. A new categorical palette `--viz-1…6` (indigo, orange, aqua, gold, magenta, blue), validated for CVD and normal-vision separation in both themes. Status colours are never series colours.
- **Command palette.** A combobox/listbox with two groups — Recent (up to 8 tasks at rest) · Actions — under one fuzzy ranking with the matched letters marked, and a key-hint footer. The v1.16 engine catalog is removed: starters and the Composer are where work is worded.
- **Settings.** Compact preference panes: a nav with accent selection, grouped rows, one pane title style. The safety floor in General reads as three points: secrets stay in the vault · storage is read-only · imports are bounded to 500 files / 256 MiB per call, audited, and Stop ends work.

## Preserved

- The product invariant: the Agent Task is the application. Direction → Execution → Work Result → Artifact.
- Result-first: banners · work in progress · Result · Work log; a one-Direction Task has no Work log.
- One Composer, one submit path; durable Executions reconnect by sequence (`after=<last seq>`).
- No approval, no plan: `import_evidence` stays inside its server-side bounds (≤ 500 files / 256 MiB per call, 1 GiB disk headroom, audited `approved_by=agent`); Stop is the brake.
- Read-only storage tools, server-side provider scope, secrets only in the vault, sanitized and bounded context, no chain-of-thought.
- The Sidecar runtime, API and migrations (head **031**).

## Contracts

The documentation contract moves to v3.0.0.

## Known gaps

- The side-pane width is remembered per device in browser storage; it does not follow the user between machines.
- The figure palette was validated against the shipped panel surfaces; a figure placed on another surface is not separately validated.
- In the light theme three series colours (aqua, gold, magenta) are under 3:1 against the white card. The validator marks this as a warning, not a failure; every figure compensates with a legend, a hover tooltip and a table view.
