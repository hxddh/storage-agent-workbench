# Storage Agent v1.12.0

**Native all the way through — one protocol, a push-driven event stream, the model's own plan, an approval policy, context compaction, `AGENTS.md`, Execution detail from the durable log, and the frontend split by responsibility. Migration 030.**

## Summary

v1.11.0 made a turn read like Codex. v1.12.0 removes what still worked like a chat backend underneath it and adds the runtime behaviours a native Agent client is expected to have. There is now exactly one wire protocol between the window and the Sidecar: the durable Execution API. The event stream is pushed, not polled, and carries the task's state so the client stops asking for it. The model keeps its own plan with a tool and the transcript shows it as a checklist. The user chooses once how gated calls are answered (ask · this session · always), and a large account survey crosses the same gate as data movement. When the context window fills, the runtime compacts and continues instead of cutting the turn short. A standing `AGENTS.md` next to the data is read every turn. Execution detail is built from the durable log. The frontend monoliths are split.

## Review of v1.11.0 (what this release corrects)

- **Two protocols.** `/sessions/{id}/messages`, `…/messages/stream` (with a `legacy_frames` translation), `…/turns/{id}/cancel`, `…/turn`, `…/actions/prepare` and an always-empty `proposed_actions` field lived beside the durable Execution API; the frontend still carried clients for them.
- **Polling everywhere.** The SSE follower polled SQLite every 120 ms; the hub's condition variable was never awaited; the client polled `/state` every 1.5 s while a stream was open.
- **No plan.** The model could not tell the user what it intended to do; the transcript had no checklist.
- **"Worked for" summed durations** of parallel calls.
- **One gate, no policy.** Every `import_evidence` call asked; `survey_account(max_buckets ≤ 500)` was unbounded autonomous work.
- **No compaction.** A full window ended in a cut-short marker.
- **Execution detail on a `/runs` `EventSource`.**
- **Monoliths:** `AgentTaskImplementation`, the runner, and `api.ts`.
- **No instructions file.**

## What changed

- **One protocol (W1).** The `/sessions` message, stream, cancel, turn and action-prepare endpoints, `legacy_frames`, `SessionMessage.proposed_actions`, `SessionMessageCreate` / `ActionRequest` / `SessionTurnState` are gone; `sessions/next_actions.py` keeps only the deterministic normaliser the summary/triage engines use. Tests submit through `POST /agent-tasks/{id}/executions` (`tests/turns.py`). The frontend clients that used the shims are deleted and an architecture test keeps them out.
- **Push transport (W2).** `task_runtime/hub.py` registers an `asyncio.Event` per follower and wakes it from the worker thread on every delta, marker and durable append; `event_stream.execution_frames` awaits it (15 s heartbeat, 2 s settle re-check). `store.refresh_task_status` appends `task.status {status, active_execution_id, queued, pending_decisions, last_execution}` to the running/waiting execution's log; `useSessionDocument` folds those frames into task state and reads `/state` only on attach, visibility change and stream end.
- **Plan tool (W3).** `agent_runtime/plan_tools.py` → `update_plan(steps)` (≤ 12 × 160 chars, redacted, CoT-stripped, budget-exempt). Each call is `plan.updated {steps}`; `stream._Segments` folds a turn's calls into ONE `plan` turn item at the first call's position; the record is never a tool row nor in `tool_activity`. `PlanCard` renders it (check / pulse / hollow dot; folds to *Plan · n/n*).
- **Approval policy and the scan boundary (W4).** `task_runtime/approval_policy.py`: `ask` (default), `allow_session` (process memory; a restart falls back to `ask`), `allow_always` (`app_settings.approval_policy`). Consulted only in `runtime.request_approval`; an auto-approval is a durable approved Decision (`scope = session | always`, `resolution_note` says which) plus `approval.granted {policy}`. `GET/PUT /settings/approval-policy` returns the policy and the gated tools; Settings → Safety is the pane. `survey_account(max_buckets > 100)` raises `survey_account_large` with `{provider, buckets, estimated_calls}`; Deny refuses; outside a durable execution the cap is clamped to 100.
- **Context compaction (W5).** `agent_runtime/compaction.py`: when the last turn's reported input usage ≥ 80 % of `model_budget.context_window`, `_run_execution` runs one tool-less streamed call (`[[storage-agent:compact]]`, private loop, 60 s ceiling, seam `COMPACT_STEP`) over the sanitized replay, stores ≤ 2 000 redacted chars as a new context version (`summary_sanitized`, `summary_through_seq` — migration 030), appends `context.compacted`, and the turn starts with a `compacted` item. The prompt builder puts `conversation_summary` in the stable half and replays only later messages. `POST /agent-tasks/{id}/compact` runs the step on demand (409 while busy, 422 without a model); ⌘K **Compact context**; the context meter drops to `after_tokens`. The overflow cut marker stays as the last resort.
- **Execution detail and the frontend split (W6).** Execution detail = `task_executions` row + `execution_events` (`tool.*`, `plan.updated`, `approval.*`, `context.compacted`, `steer.applied`, `message.completed`, `execution.status`, `work_result.recorded`) + `GET /sessions/{id}/activity/{call_id}` on expand + the Work Result text; no `EventSource`, no `/runs`. *Worked for …* is the group's wall clock (`started_at` / `finished_at` on records and events; max duration as the fallback, never a sum). `AgentTaskImplementation` → `TaskDocument` · `TaskBanners` · `TaskComposerHost` · `useApprovals`; `api.ts` → `api/runtime.ts` · `api/tasks.ts` · `api/settings.ts` · `api/providers.ts` behind a barrel.
- **`AGENTS.md` (W7).** `agent_runtime/instructions.py` loads `STORAGE_AGENT_DATA_DIR/AGENTS.md` (or `STORAGE_AGENT_INSTRUCTIONS`): ≤ 8 000 chars, redacted, injected after the skills catalog in the stable prompt half, never executed, never above the safety rules. `GET /settings/instructions` reports status only; Skills & bridges → **Open instructions file** (Tauri `open_app_folder("data")`).

## Preserved

- One durable Agent Task runtime; one submit path; sequence-only stream recovery; steer/stop/resume/verify/revisit semantics; runtime titles; reasoning effort; the v1.11 transcript turn, inline approvals and Artifacts panel.
- Read-only allowlist, vault, redaction, server-side scope, bounded/sanitized context, explicit Decisions for data movement and large scans, no chain-of-thought persistence. A policy can only answer a gate that exists.
