# Storage Agent v10.1.0

**A calmer, more truthful window.** v10.1 is a presentation and reliability release on the v10 Agent core: the window gets a warm, ink-blue visual system and a clearer home, conversation and Settings, while the item stream, secret boundary and Turn lifecycle become more exact. No migration, no API shape change, and no change to the read-only storage floor.

## A quieter window

- **A new visual system.** Warm graphite and paper surfaces, one ink-blue accent, a five-step type scale with a 36px home title, and three radii make the window read as one instrument rather than a collection of panels.
- **The home is an editorial start.** An eyebrow, one greeting, the Composer, three starter cards and one calm *Needs attention* card replace the old centred hero. A starter still only fills the Composer; the home submits nothing.
- **The conversation is easier to scan.** Requests are compact bubbles, the work line reads *Running…* while a tool runs, findings sit in one bounded card, next steps are full-width suggestions, and the live answer is announced once.
- **Settings is a real workspace.** The save row is a pinned toolbar above the fields, so it stays in reach without covering a credential field; the storage form fits through Secret key at the default window height.
- **System theme.** Theme is now System · Light · Dark. System follows the OS and reacts when the OS changes; the menu shortcut persists the choice instead of only changing the current window.
- **Mobile is deliberate.** Attention rows wrap the issue title and bucket list instead of truncating them; the sidebar is an overlay, and Settings becomes one column.

## A more truthful Agent

- **The item stream stays in order.** A parallel tool output can no longer publish `seq+1` before `seq`; a follower that sees a gap replays the durable items before advancing.
- **Withdrawn requests stay withdrawn.** A queued Direction withdrawn before it ran is no longer a version, cannot become the head, and cannot be resumed.
- **Stop keeps what was written.** Text written before the tool call that Stop interrupted is still the answer so far.
- **No steer is dropped.** Steers that arrive after the last model call become the next Direction on a completed, failed or stopped Turn, with a visible *carried* notice.
- **Compaction is inspectable.** The summary that stands in for earlier Turns can be opened from the work line instead of existing only as a generic note.
- **Quick Ask fails visibly.** A failed task or an unreachable Sidecar renders its reason instead of a blank body.
- **Title work is off the critical path.** A task is named in the background; a slow endpoint no longer delays the next queued Turn or holds a database connection across the model call.

## Secret boundary

- Exact values held in the local vault are masked from Directions, steers, attachments, tool arguments and targets, tool results, live streamed text, audit rows, notes, and reports — in addition to credential-shaped patterns.
- The final report and every item payload pass through the same scrubber, so a future caller cannot bypass the boundary by writing a new field.

## Performance

- Streamed text rerenders only the Turn that owns it; the sidebar and Composer no longer rerender for every token.
- Long conversations keep their sections memoized while the live segment grows.

## Verification

- Frontend: typecheck, 162 Vitest tests and the production build passed.
- Sidecar: `ruff`, 857 tests, and the packaged PyInstaller deep smoke (`/health` + selfcheck) passed.
- Real Sidecar + Chromium: 19 Playwright E2E tests passed, including WCAG AA contrast for home, conversation, bucket sheet and Settings in both themes.
- The desktop contact sheet was regenerated in dark, light and Chinese, with mobile home and attention states inspected.

The release workflow produces ad-hoc-sealed (not notarized or Authenticode-signed) macOS, Linux and Windows installers from this exact source.

## Upgrading

No migration. Existing providers, estate, notes, tasks and item streams carry over. Storage access remains read-only; fixes remain text the user applies.
