# Storage Agent v13.0.0

**Storage is a capability, not a page.** v13 removes the last storage-console
surfaces from the window. The Task is the object; the estate is what the Agent
remembers; one Composer is the only input. The runtime, the 15 read-only tools,
the item stream, the schema (head **2**) and the safety floor are unchanged.

## The window

- **No Storage page, bucket page, estate picker or open-Issue counter.** The
  sidebar is New task, search, the task list and Settings. Accounts, buckets,
  Issues and notes are data the Agent reads and writes through its tools; they
  are not a resource tree the reader has to browse.
- **A task is a workspace, not a chat.** The objective is a compact heading.
  Under it, the deterministic result the tool returned comes first — a survey
  table, listing, configuration view or fix — then the Agent's short
  interpretation, its findings, and one quiet receipt (`2 checks · 1s`). There
  is no user or assistant bubble, no next-step prompt and no second suggestions
  block.
- **The run is visible while it is work.** Every real call, its target,
  progress and result appears live, with commentary and steers in order. Once
  settled it folds to the receipt.
- **Evidence is the raw record.** One row per call expands to its arguments and
  output; the rendered artifact belongs to the Task, once. Save report, files
  and usage follow. No second page, no Back control, no duplicated table.
- **One Composer, one behaviour.** Centred on Home, docked on a task. At rest
  it is a paperclip, the model chip and Send; while work is live, *Add to the
  request* and Stop. There is no `@` estate picker and no account/bucket chip:
  name what you mean and the Agent resolves it, or asks when it is ambiguous.
- **Settings has Connections, not Storage.** Models and storage services are
  configuration. Watch stays with each connection; notes stay Agent memory.
- **Home is one sentence and one Composer.** No starter cards, account lines,
  Issue table, readiness paragraph or storage navigation.

## Cheaper follow-ups

- A large deterministic tool result is still kept whole in the item stream for
  the workspace, but later Turns replay a compact, enveloped digest of it. The
  current Turn still reads the result it actually received. A survey table no
  longer taxes every follow-up.
- The digest is valid JSON by construction (lists are trimmed, never cut mid
  document), keeps the facts needed to continue, and points back to the tool
  for a row or a full value.

## Refinement

- Home no longer repeats the greeting as the Composer placeholder; the input
  says what it accepts (`Describe a problem, a bucket, or a log…`).
- Settings is a full-screen surface on a narrow window, with one row of section
  tabs and a focused scrolling body.
- The sidebar brand mark is the Agent spark, not a storage cylinder.
- The retired storage-sheet stylesheet and its dead responsive rules are gone.

## What it preserves

One Agent, one submit path, one item stream, the Turn tree, forks,
queue/withdraw, steer/stop/resume, compaction/finalize, the live trace, rendered
deterministic results, all 15 tools, schema head **2**, read-only storage and
the secret boundary. No migration. Existing connections, estate, notes, tasks
and item streams carry over.

## Limits

Builds remain ad-hoc/unsigned in the trust-store sense: macOS is not notarized
and Windows is not Authenticode-signed. The live model eval remains opt-in and
is not part of the default gates.
