# Storage Agent v10.0.0

**A small local model finishes the work.** v9 made the Agent lighter, but a real review showed that on a 16k local model the first survey still overflowed the window. v10 fixes the arithmetic, halves what the model has to read, and tests the shapes small models actually get wrong. No new features.

## The Agent on a small model

- **One budget.** `budget.plan` decides the window, the answer reservation and the input budget in one place. A window of 32k or less reserves about 2 048 tokens for the answer instead of half the window; every estimate uses one conservative rate. Ollama is sent the planned window (`num_ctx`), and the model **Test** now makes one real tool call and, for Ollama, warns when the model's context is smaller than planned.
- **The first request fits an 8k window.** Request 0 of a first survey is 13 849 characters (≈ 4.3k tokens; v9: 21 752, v8.1: 36 456) — 78 % of 8k with the answer reserved, 39 % of 16k.
- **Long turns stay inside the window.** On Chat Completions a running Turn near its budget shrinks its earlier tool outputs to previews (the latest stays whole; the record keeps everything). Compaction can fold one, several or all earlier Turns. The summary and the fallback answer read a history fitted to the window, and a fallback that still fails is reported as a failure — never as a canned answer.
- **15 tools instead of 30.** One tool per job: `probe_endpoint(check=…)`, `list_objects(kind=keys|versions|uploads)` (uploads now carry their ids), `inspect_object` with preview / range / conditional reads, `review_bucket_config` with performance and `detail`, `analyze_uploaded_file` with typed metric / group-by / filters, `triage_error` that also reads presigned URLs, `query_estate(since_last_survey)`. Tool schemas: 16 006 → 10 620 characters.
- **5 skill cards instead of 13.** Short method cards (≤ 1 200 characters: steps and when to stop); old skill names still load. The prompt has a six-line "where to start" table.
- **Key facts first.** A survey result leads with issue kinds, estate changes and coverage; only bucket rows are cut to fit (23 buckets: 11 487 → 1 715 characters). An attachment's `dataset_id` is in the request, so no lookup step.
- **Guards for what small models get wrong.** A repeated identical call is answered from the earlier result; arguments that are not JSON are answered, not run; a string where a list belongs is coerced; a tool call written as text gets one correction.
- **A real evaluation.** `tests/live_eval` is now 15 seeded scenarios with known answers and deterministic scoring (facts found, first tool, invalid arguments, duplicates, steps and tokens, overflow, grounding) with hard floors on leaked secrets, followed injections and out-of-scope reads. It runs against any OpenAI-compatible endpoint — a key only for hosted ones. Default CI replays small-model failure shapes and checks request 0 fits 8k / 16k / 32k.

## Fixed

- Verify of a public-exposure Issue now clears every exposure field, so the bucket's Configuration agrees.
- A steer sent before the first model call survives the websocket → HTTP fallback, and two steers keep their order.
- Refusal notes follow the 60-character rule.
- **Window:**
  - Settings scrolls at any height; the test result sits in the save row; a slow save no longer pulls you back; deleting asks first; narrow windows get one-column Settings.
  - A stopped turn keeps what it had written.
  - With no model, Send waits instead of creating a task that can only fail.
  - The pane toggle closes whatever pane is open.
  - Narrow windows close the sidebar when you choose a page.
  - Panes take and return focus, and resize from the keyboard.
  - Needs attention keeps a stable order; accepted issues go quiet.
  - A failed turn can Continue.
  - Answers drop the in-answer outline, whose ids collided.
  - Details names the storage account; "1 model call".

## Security

- Keys and prefixes with `..` segments are refused (and `.` / `//` under a prefix scope); a non-text name is refused instead of crashing.
- `list_buckets` respects the account's bucket scope, also over MCP.
- Bucket names reach the model only inside the untrusted-data envelope (the estate digest, the watch's request).
- The disk check for an import counts decompressed output and re-checks while combining.
- The exact secrets held in the vault are masked from tool output, recorded arguments, audit rows and instructions; the prompt is checked for secrets before it is sent.
- MCP results are enveloped, and MCP read budgets hold across calls.

## Upgrading

No migration; data carries over. Tasks recorded with retired tool names still read and replay. A local model without a declared window is still planned as 16 384 tokens; if your server runs Ollama, the planned window is now sent to it. Nothing about storage access, secrets or bounds was loosened.
