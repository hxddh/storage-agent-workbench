# Storage Agent v3.1.0

**Outputs made real: the report, the findings and the side pane now say what the Agent Task actually recorded, and the design system is finished. No migration (head stays 031); the runtime, the security floor and the single submit path are unchanged.**

## Summary

v3.0.0 gave the window a design system and put the Task's durable outputs in a side pane. v3.1.0 makes those outputs agree with the record:

- The Task report is rebuilt: it opens on the conclusion the Agent recorded, lists findings once, and reads in the reader's language.
- The Result and the Evidence tab read one findings list, and each finding links to its evidence when a chain was recorded.
- ⌘I toggles the side pane and always lands on an output that loads.
- The model chip tells the truth when the runtime is offline.
- No component carries a raw colour or type utility any more; the figure palette clears 3:1 in the light theme.

## Review of v3.0.0 (what this release corrects)

- **The report did not lead with the answer.** It opened on bookkeeping; the conclusion the model recorded with `record_conclusion` was not its head, empty sections were written anyway, and it was English only.
- **Two findings lists that did not agree.** The Result showed the conclusion's findings; the Evidence pane showed the findings recorded during the work, with its own count. A separate list of provenance marks sat under the figures.
- **⌘I could open on nothing.** On a Task without Evidence, ⌘I opened a selection with nothing behind it and the pane read *No report has been generated*.
- **Offline looked like setup.** With the runtime unreachable the model chip read *Set up a model…*, inviting an action that could not succeed.
- **The design system was not finished.** Components still carried raw colour and type utilities, three type aliases kept a second set of names alive, and some status still read as coloured prose.
- **Light-theme series under 3:1.** Aqua, gold and magenta fell under 3:1 against the white card (a v3.0 known gap).

## What changed

- **Task report** (`sidecar/app/sessions/session_report.py`, `GET /sessions/{session_id}/report?lang=en|zh`).
  - `lang` is optional and defaults to English; the frontend passes the UI language (`api/tasks.ts getTaskReport(id, lang)`).
  - Order: title + one meta line (Directions · tool calls · when) → **Goal** (the task goal, else the first Direction) → **Conclusion** (the latest recorded `record_conclusion` answer; without one, a note plus the latest answer excerpt; with no Work Result, *No Work Result yet*) → **Findings** (one list: the conclusion's findings, then those the Agent recorded while working, then the analyses' findings, deduplicated on their text, most severe first, severity words localized) → **Next steps** (the conclusion's) → **Investigation / 工作过程** (per Direction) → **Coverage and gaps** (grounded in · not verified · left open · limitations, derived from the tool trace and memory) → What the Agent established → Tools run → Analyses → Attached evidence → Error triage → Rule-derived suggestions → Usage → Audit trail → **Safety** (always).
  - A section with nothing behind it is not written.
  - Only the words the module authors are localized (EN/ZH); the Agent's own words are reproduced as recorded, never translated.
  - Still redacted, bounded and one-line-sanitized: no raw rows, no secrets, no chain-of-thought.
- **One findings model** (`frontend/src/lib/findings.ts` `unifyFindings`).
  - The Result and the Evidence tab read one list: the recorded conclusion's findings, joined by the findings recorded while the Agent worked (`session_findings`, via the provenance projection), deduplicated on their words, most severe first. A conclusion finding the work also recorded takes that record's id.
  - Each finding carries its evidence chain when one was recorded: an **Evidence** link ends the row (hover previews the source call; click opens the side pane on that finding). A finding with no chain says *No direct evidence*.
  - The separate list of provenance marks under the figures is gone.
  - A Result without a recorded conclusion shows the answer, then the recorded findings — records, never guesses.
  - The Evidence tab count equals that list (+ attached files). The tab reads Findings (each expands to detail and source: in the conclusion / recorded while working · confidence · tool · time · gap) → Current understanding → Attached evidence.
- **⌘I** toggles the side pane, opening on the first output the Task has. A selection with nothing behind it settles on the output the pane shows, so the Report loads.
- **Truthful chrome.** When the runtime cannot be reached the model chip reads **Runtime offline** with a danger dot and is not clickable.
- **Design system finished.**
  - No component (`*.tsx`) carries a raw colour or type utility (guard in `frontend/src/components/v310.test.tsx`); surfaces compose `components/ui.tsx` and semantic classes.
  - New stylesheets under `frontend/src/styles/` — `markdown.css`, `settings-panes.css`, `artifacts.css`, `overlays.css` — imported after `agent/native-*.css`.
  - The type aliases `--text-xs`, `--text-base`, `--text-lg` (and Tailwind `xs` / `base` / `lg`) are removed: five sizes, five names — `--text-2xs` 11 · `--text-sm` 13 · `--text-prose` 15 · `--text-xl` 20 · `--text-2xl` 28.
  - `.ui-scrim` is the one scrim; it fades as a sibling of the opaque sheet.
  - Status reads as a dot or badge next to neutral text in settings test results, the cloud tester, S3 error cards, call detail and tool results — no coloured prose.
- **Figures.** The light theme's orange, aqua, gold and magenta are stepped darker in the same hues (`--viz-2 #e05a26`, `--viz-3 #11906a`, `--viz-4 #ad7d00`, `--viz-5 #d24e86`) so every series clears 3:1 on white and panel surfaces; CVD separation and the normal-vision floor were re-validated and all hard checks pass in both themes. Inventory ranked bars align to the top of their column.
- **Palette.** The v1.16 `prefill` action, unused since v3.0, is removed.

## Preserved

- The product invariant: the Agent Task is the application. Direction → Execution → Work Result → Artifact.
- Result-first: banners · work in progress · Result · Work log; a one-Direction Task has no Work log.
- The window: sidebar · title bar · one Task document · one Composer, plus the one resizable, closable side pane (352–880px, overlay below ~1100px).
- One Composer, one submit path; durable Executions reconnect by sequence (`after=<last seq>`).
- No approval, no plan: `import_evidence` stays inside its server-side bounds (≤ 500 files / 256 MiB per call, 1 GiB disk headroom, audited `approved_by=agent`); Stop is the brake.
- Read-only storage tools, server-side provider scope, secrets only in the vault, sanitized and bounded context, no chain-of-thought.
- The conclusion is only what `record_conclusion` recorded; the UI and the report never guess one from prose. Evidence and gaps stay derived from the tool trace.
- The Sidecar runtime and migrations (head **031**). The only API change is the optional `lang` query parameter on the report route.

## Known gaps

- The side-pane width is still remembered per device in browser storage; it does not follow the user between machines.
- The report localizes only its own words; a Task whose Directions and answers are in another language reads mixed, by design.
- Findings are deduplicated on their normalized words; two findings that say the same thing in different words stay two rows.
- The figure palette was validated against the shipped panel surfaces; a figure placed on another surface is not separately validated.
