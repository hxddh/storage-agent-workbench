# Storage Agent v7.0.0

**Simpler to use, exact when you follow up.** v7 keeps the v5/v6 core — one native Agent, one item stream, one submit path, read-only storage — and removes what made the window complicated: a task is now one conversation, the estate folds into the home and a bucket sheet, and one Details pane replaces three tabs. There is no plan mode, todo list, approval step, mode switch, sub-agent or workflow builder.

## Summary

- **A task is one conversation, oldest first.** Your request, one activity line for what the Agent did (*Reviewed bucket configuration acme-www* while it works; *3 steps · 12s* when done, expanding to each step), the answer as it streams, then the answer with its findings and figures. The result-first page, the outputs bar and the Work log are gone.
- **Follow-ups are exact.** Asking again — while the Agent works, after a reload, after an edit — never reorders, drops, duplicates or leaves a turn showing *Working*. Suggested next steps from the last answer fill the Composer.
- **The home says what needs attention.** One readiness sentence when something is missing, then the open Issues most severe first; a row opens the bucket in the side pane. The separate Estate area and the Home entry are gone from the sidebar.
- **The bucket sheet.** Issues (Show fix, Verify; Open task and Accept risk in a menu), configuration with deviations first, notes (Enter adds) and history, folded. The fix is CLI · Terraform · JSON with an impact preview in plain sentences.
- **Details.** One pane for a task: Save report, usage, every tool call, attached files.
- **Plainer words.** *Send*, *Add to the request*, *Stop*, *Needs attention*, *Continue*. Notes on an account and on all storage live in Settings.
- **Your language on first run.** Until you choose, the window follows the system language (a Chinese system opens in Chinese).
- **Polish.** Icon send/stop buttons, a message bubble that reads in both themes, table actions on hover, the conversation reflowing beside the pane, tool rows that name the storage account instead of its id.

## Fixed

- The model's history for a follow-up interleaved the calls and outputs of a parallel batch and put commentary in a shape Chat Completions endpoints merge badly; strict endpoints rejected the request. History now replays in branch order, calls then outputs, with commentary as assistant output messages and a recorded conclusion as its call.
- A queued follow-up could run before the continuation of an interrupted turn after a restart; the continuation now runs first and the follow-up is re-parented onto it.
- Withdrawing a queued request orphaned the requests queued after it; they are re-parented onto its parent.
- A steer could reach the model twice (from history and from the input filter), and the running turn's open text segment was not closed before it.
- Stopping wrote two lifecycle notices.
- Reasoning models were sent a sampling temperature they reject.
- The window replaced its state wholesale on every reload (dropping items that had arrived), opened the stream from the start, kept stale live text, missed a turn that settled between the snapshot and the stream (stuck on *Working*), and only saw a new version of an edited request after a reload. The server now sends a `turn` event and the current `state` whenever a stream opens; the window merges snapshots and streams after the snapshot's `last_seq`.
- A new follower could receive a live delta twice.

## API

New SSE event `turn` (a Turn's public row); `state` carries `head_turn_id` and is sent when a stream opens; the snapshot's `task` carries `head_turn_id`; `GET /settings` returns `language: null` until one is chosen. No migration. See `docs/api.md`.

## Upgrading

Data carries over unchanged (migration head stays at 2). Nothing about storage access, secrets or bounds changed.
