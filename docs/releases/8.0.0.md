# Storage Agent v8.0.0

**Fewer things, each working.** v8 adds no feature. It fixes what a full review of v7 found, and removes what did not earn its place — the same native core (one Agent, one item stream, one submit path, read-only storage), with less around it. There is no plan mode, todo list, approval step, mode switch, sub-agent or workflow builder.

## Fixed

**The Agent and its history**
- Adding to a request while a tool was running replaced that tool's result with "interrupted" in later history. The steer now replays after the tool returns.
- Adding to a request during the final answer was acknowledged but never reached the model. It now becomes the next request when the turn completes, and the model reads it once.
- Withdrawing a queued request could race the worker and the request ran anyway. Withdraw and run now claim the turn atomically; exactly one wins.
- After switching versions, a withdrawn request could come back onto the branch and be sent to the model. A withdrawn request is never part of a branch, and cannot be "resumed".
- A blank request or steer was accepted; `%` and `_` in task search matched everything; an absurd stream position raised inside the stream.

**What it remembers**
- A review of a bucket that does not exist added that bucket to the estate. A review in which every check failed now records nothing.
- The reason a risk was accepted stayed in the notes (and the prompt) after the risk went away. It leaves when the issue resolves.
- Shortening a watch interval did not bring the next check closer.

**The window**
- Choosing a model in the Composer's model menu sent the half-written message.
- In the desktop app the native menu, deep links and shortcuts were re-subscribed on every streamed token, and a task opened from a link could pull you back to it.
- A late snapshot could leave a finished task showing *Working*.
- Sidebar search reopened the live feed on every keystroke, and a slow answer could overwrite a newer one.
- ↑/↓ while renaming a task switched tasks; Escape in a note or a menu closed the whole side pane or Settings.
- Text typed in one task's Composer followed you to the next task.
- An issue resolved by Verify disappeared into the folded list before its result could be read.
- Quick Ask could create two tasks on a double Enter and showed the answer twice.
- Failures of model test/delete/activate, watch changes, model switching and Save report were silent; they now show an error.

## Simpler

- **30 Agent tools instead of 42.** One configuration review (`review_bucket_config`, with optional aspects), one object inspection (`inspect_object`), one conditional/range read test (`test_object_read`); credential checks are `list_buckets`; what is already known is `query_estate`. The schema every model call carries is ~14 % smaller. The read-only MCP bridge follows the same tools and never exposes `note` or `record_conclusion`.
- **No dollar estimates.** The price table could never be confirmed from the window, so dollars never appeared. The simulator now projects bytes per storage class and says it never quotes a price.
- **No command palette.** ⌘K focuses the sidebar search; New task and Settings keep ⌘N and ⌘,.
- **Settings has three sections.** Skills, the standing-instructions file and the MCP bridge sit under General › Advanced.
- **The home groups what needs attention.** One row per kind of issue, naming every bucket it was found on; every open issue is reachable. Storage that was never checked says so instead of "nothing needs care".
- **The bucket sheet shows only what deviates** — exposure, a failed read, a missing protection. No "Show all".
- **15 bundled skills instead of 20**; removed dead endpoints (task file list, artifact, skill body, price table), dead code, strings and styles.

## API

Removed: `GET /tasks/{id}/files`, `GET /tasks/{id}/artifacts/{id}`, `GET /skills/{name}`, `GET`/`PUT /settings/price-table`. `POST /tasks` no longer takes `title`. Blank `direction`/`text` is a `422`. A turn may carry a `carried` notice. No migration. See `docs/api.md` and `docs/tools.md`.

## Upgrading

Data carries over unchanged (migration head stays at 2). Earlier tasks that used retired tool names still read and replay; their rows show a plain label. Nothing about storage access, secrets or bounds changed.
