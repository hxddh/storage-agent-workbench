# v0.92 — Agent OS rebuild

v0.92 is a product-model replacement, not a visual refresh.

## Why the old model is being removed

The historical client is structurally a chat application: navigation rail → thread → local buttons → modal/full-canvas detail overlays. That model keeps the conversation as the permanent center of gravity even when the user is actually reviewing evidence, inspecting execution, comparing runs, or reading a durable report.

Modern Agent clients have moved past this model. The important lesson is not their palette or iconography; it is that long-running Agent work needs a command center that lets a person delegate, supervise, redirect, inspect, and review several kinds of work without forcing every task back through a chat transcript.

## Reference principles

### Codex

- Agent work is organized as persistent threads/projects, not disposable prompts.
- Long-running work is supervised and redirected rather than held inside one synchronous request/response interaction.
- Parallel agents need isolated execution contexts and a clear place to review outcomes.
- Review is part of the Agent workflow itself: findings/changes are inspected where the task lives.

### Cursor Agents Window

- The Agent can be the center of the product while deep work surfaces remain first-class.
- Files, changes, browser, terminal, PR and canvas surfaces can take the full work area.
- When a work surface is full-screen, the prompt collapses into a steering affordance rather than keeping a large chat panel permanently beside it.
- Tool activity density is progressive disclosure, not an all-or-nothing debug console.
- Async subagents and queued/multitasked work require explicit run/task identity.
- Long-lived goals, event-triggered work and always-on agents require persistent status beyond a single turn.

## v0.92 product model

```text
Agent OS
├── Investigation Navigation
│   ├── active / pinned / archived investigations
│   ├── search / command palette
│   └── goal + run status at a glance
├── Command Bar
│   ├── active investigation / goal
│   ├── Work Surface switcher
│   ├── connection / Agent status
│   └── focus / global commands
└── Work Area
    ├── Timeline    — questions, decisions, Agent narrative, steering
    ├── Evidence    — findings, memory, files, audit/activity evidence
    ├── Runs        — explicit auditable execution and sub-work
    └── Report      — durable technical output
```

The Timeline is one surface. It is not the application shell.

## Interaction contract

1. **Every long-running thing has identity and status.** A run or future subagent is not a spinner attached to a message bubble.
2. **Steering is always reachable.** Deep work surfaces may fill the window; steering must not require returning to the Timeline.
3. **Work surfaces replace one another.** Evidence and reports are navigation destinations, not modal cards layered over chat.
4. **Full-screen is geometric, not decorative.** Focus mode removes surrounding navigation; it does not scale a modal to look large.
5. **Timeline is chronological.** Cross-cutting state such as findings, memory, audit and run inventory belongs to dedicated surfaces.
6. **Evidence stays inspectable.** Sanitized tool input/output, gaps, source identity and audit ordering remain available even when default density is compact.
7. **Answers are documents.** Technical prose, headings, tables, code, evidence references and conclusions use document hierarchy. Rounded cards are reserved for controls or state that genuinely behaves like a discrete object.
8. **Keyboard navigation is semantic.** Surface switching, turn navigation, search and command palette operate on product concepts rather than DOM accidents.
9. **Safety boundaries survive the UI rewrite.** Read-only guarantees, credential handling, approval boundaries and sanitized persisted evidence are not downgraded to make the redesign easier.

## Architectural contract

The target dependency direction is:

```text
App
  -> Workbench state + shell
      -> Investigation navigation
      -> Timeline feature
          -> turn runner / session transport / viewport controller
          -> answer document renderer
          -> steering surface
      -> Evidence feature
          -> persisted findings / memory / activity / audit / files
      -> Runs feature
          -> run list / run review
      -> Report feature
          -> durable report reader / export
```

`ThreadImplementation.tsx` and the old full-canvas overlay implementations are migration sources, not architecture. v0.92 is not complete while public workbench behavior still depends on hidden duplicate headers/listeners or DOM-bridge clicks into those components.

## Validation gates

The rewrite may intentionally invalidate old visual/selector assumptions, but it must not weaken behavioral coverage. Replacement gates must continue to prove:

- real Sidecar end-to-end turns;
- streaming and interruption/steering behavior;
- session recovery and long-thread navigation;
- evidence honesty and sanitized payload inspection;
- credential-free CI;
- keyboard/focus accessibility;
- Chinese UI paths where product-owned prose is localized;
- macOS, Windows and Linux packaging/runtime smoke;
- full-canvas geometry for true work surfaces.
